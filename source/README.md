# 准构 CAD

网页端工程实体建模工作台。使用 OCCT WebAssembly / replicad 建立边界表示实体，Three.js 显示网格；若浏览器禁用 WebGL，则用 Canvas 2D 显示模型投影。三张正投影视窗由几何内核输出可见线及隐藏线。

## 开发

```sh
npm ci
npm run check
npm run dev
npm run build
```

## 使用范围

- 基础形体：长方体，中心位于 XY 原点，底面 Z=0。
- 运算形体：圆柱、长方体；布尔差集、并集、交集。按模型树顺序计算。
- 切割：X/Y/Z 法向平面与坐标值，保留正侧、负侧或两侧。
- 工程文件：JSON，包含参数、运算顺序、切割配置。浏览器自动保存本机副本，也可手工导入导出。
- 几何结果：STEP 导出实体；STL 导出三角网格。
- 单位：mm。几何内核校验实体拓扑；显示网格离散公差 0.08 mm，不能当作制造公差。

本版尚未规定制造或测量误差阈值；输出前需在目标 CAD 软件中验证 STEP 往返和尺寸。三视图为独立正投影视窗，未包含标准图纸排版、尺寸标注或公差注释。任意方向的切割平面尚未开放。

## 基础模型库

支持长方体、圆柱、圆锥、圆台、球体、圆环。左侧六个按钮新建独立模型（会替换当前文档，可撤销），右侧可以切换基础形体并保留运算历史。添加形体运算后，也可从六种工具实体中选择。

圆柱、圆锥、圆台底面位于 Z=0；球体和圆环以原点为中心。圆环参数 R 表示旋转轴到管中心的距离，r 表示管半径，要求 R>r>0。旧版 JSON 项目未指定基础形体时仍按长方体读取。

`npm run test:geometry` 检查六种实体的解析体积、OCCT 有效性、三个方向的投影、STEP 生成和中心平面切割；也检查圆锥布尔差集及新旧项目格式。`scripts/patch-replicad.mjs` 修补 replicad 1.2.1 空隐藏线分组报错；Vite 同时在预览及 Worker 构建中应用此修补。

## 手机和平板

同一网址在不超过 980 px 的视窗中采用纵向布局和底部导航。基础模型库、模型树与三视图可横向滑动，参数输入框保持可读尺寸。模型可单指拖动旋转，双指缩放，或用加减按钮缩放。桌面端保持多栏工作区。

`tests/mobile.html` 是开发环境的窄屏检查页，包含 390 px 和 320 px 的独立视窗；不进入生产构建。已在这两种视窗下检查页面没有整体横向溢出、输入控件可见以及切割导航和计算。未做实体手机硬件兼容性测试。

## 斜切和多刀切割

切割次数可配置 1～20 刀，每刀独立启用、设置过点、转角、保留方向，按编号顺序作用于上一刀结果。第 1 刀保存在原有 `slice` 字段，后续刀保存在 `additionalSlices`，旧工程仍按一刀读取。新增刀默认复制上一刀参数并沿参考轴增加 10 mm，用户可逐刀修改；次数表示配置的刀数，禁用或没有穿过实体的刀不会增加切面。

切割坐标先在参考法向轴上确定固定过点，随后绕经过该点的全局 X、Y、Z 轴依次旋转，角度单位为度，范围为 -360～360，正向遵循右手定则。正侧沿最终法向。橙色轮廓和短法向线只显示当前刀，在未启用时也可查看方向。绕当前法向旋转可能不改变切割平面。

`npm run test:slices` 覆盖：45 度已知棱柱体积（1/7 mm³）、两侧体积守恒、轴向兼容、旋转顺序、三视图与 STEP 生成、禁用刀、连续两刀切成三体、追加 30 度刀切成六体、新旧工程数据和非法角度。斜切结果分侧使用实体体积质心，避免边界盒中心恰好落在斜面上导致误分侧。
## 引擎加载与恢复

首次打开会下载 OCCT 引擎，页面区分线程启动、下载字节进度、内核初始化和实体重建。下载最多等待 3 分钟；启动、初始化或计算在 2 分钟没有相应进展时会停止等待并显示错误。重试会重新创建计算线程，并保留最后一次输入的工程参数；保存工程参数在引擎未就绪时仍可使用。

初始化前的修改只保留最新一次，计算期间最多保留一个后续请求，避免手机堆积无用的重建任务。`npm run test:engine` 检查真实 HTTP 分块下载、错误响应、下载停滞、线程/计算超时、保留参数重试以及真实 OCCT 自定义初始化。具体手机浏览器和网络仍需实机验证。

引擎原始大小为 22,942,327 字节（22.94 MB）；进度按十进制 MB 显示完整大小，实际网络流量会受 HTTP 压缩影响。成功初始化后将引擎二进制保存在当前浏览器的 Cache Storage 中，后续优先本机读取；引擎文件 URL 变化时才重新下载对应版本。缓存损坏、空间不足或浏览器禁用缓存时会安全回退。清理浏览器数据、更换浏览器或浏览器回收网站存储后需要重新加载。缓存命中仍需要初始化内核及重建当前实体，不能保证页面秒开。

## 下载线路

缓存未命中时，并行接收 GitHub Pages、JSDMirror 和 jsDelivr 三条公开文件线路的前 64 KiB，选择先准备好的数据流继续下载，取消其余连接。选中流若停滞会尝试剩余线路，总等待预算仍为 3 分钟。不会并行完整下载三份引擎；但探测、浏览器缓冲与故障重试会产生少量额外流量。所有下载结果均须通过固定 SHA-256 校验，与当前 OCCT 文件逐字节一致后才能使用。线路选择不能保证任意地区网络都更快，缓存命中时不探测这些线路。

`tests/engine-speed.ts` 是可选真实网络测量，结果只代表运行环境，不能代替国内手机实测。先用 esbuild 将其打包为 Node ESM，再运行输出所选地址、完整字节数、耗时及校验结果。`tests/engine.ts` 包含先收到数据的线路选择、取消其他连接、错误文件回退和选中流中途停滞的本地 HTTP 测试。
